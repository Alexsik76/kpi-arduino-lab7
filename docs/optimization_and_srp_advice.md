# Project Optimization and SRP Advice

This document outlines recommendations for improving the `kpi-arduino-lab7` project, focusing on the Single Responsibility Principle (SRP) and performance optimizations.

## 1. Single Responsibility Principle (SRP)

The `TrackingSystem` class in `core.py` currently handles multiple responsibilities:

1.  Hardware initialization (Servos, Camera).
2.  AI processing (Face Detection).
3.  Control logic (PID).
4.  Data Logging.
5.  Image processing (drawing rectangles/circles).

### Recommendations

- **Separate Visualization**: Move the drawing logic (drawing rectangles and circles on the frame) out of `core.py`. Create a `Visualizer` class or a utility function in `app/utils`. `TrackingSystem` should only care about _tracking_ logic, not how it looks to the user.
- **Configuration Management**: There are many hardcoded values (PID constants, camera resolution, servo limits). Move these to a `config.py` file or a configuration class. This makes tuning easier without modifying the core logic.
- **Controller Abstraction**: `TrackingSystem` initializes `PicoController` directly. Consider dependency injection where the hardware controller is passed in. This would allow for easier mocking during tests.

## 2. Optimization Tips

### Threading & Concurrency

- **Current State**: You are using `cv2.setNumThreads(4)` which is good for RPi 5.
- **Recommendation**: The `_loop` method runs sequentially: Read Frame -> Detect Face -> Calculate PID -> Send Command.
  - _Camera Reading_: `cap.read()` is blocking. moving camera reading to a separate thread (Producer-Consumer pattern) can significantly increase FPS, as the main loop won't wait for the camera hardware.
  - _Move Command_: Sending UART commands is relatively fast but can be blocking. Ensure `pico.send_cmd` is non-blocking or extremely fast.

### Image Processing

- **Resolution**: You are resizing to 320x240 for detection. This is excellent.
- **Grayscale**: Face detection often works equally well on grayscale images. Converting `input_frame` to grayscale (`cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)`) before passing it to the detector might save some CPU cycles, though YuNet might expect RGB. _Verify if YuNet supports grayscale input for your specific model version._

### Control Logic (PID)

- **Derivative Noise**: You are using a simple difference for the D-term `(error - prev_error) / dt`. In real-world systems, this can be noisy. Consider using a moving average of the error or the derivative term itself to smooth out servo jitter.
- **Dead Zone**: You have implemented a dead zone, which is good. Ensure it's tuned to the mechanical slack of your servos.

## 3. General Python Tips (PEP 8)

- **Type Hinting**: Add Python type hints (e.g., `def compute(self, current_val: float, target_val: float) -> float:`) to improve code readability and help IDEs catch errors.
- **Docstrings**: Ensure every class and public method has a docstring explaining _what_ it does, _args_, and _returns_.
